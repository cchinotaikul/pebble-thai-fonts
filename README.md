# Pebble Thai Language Pack

## Background and Disclosure

I tried some pre-generated Thai character packs for the Pebble Time 2 and
using pre-made tools, but none of them seem to look right,
especially when next to the default English/Latin fonts. I therefore
used Claude to help generate my own, based on Pyxzure's tool.

After a few iterations, I think it came up with a good character pack that is
more legible and consistent with the Latin characters, so I'm sharing the
pack and the tools created by Clade in case others want to use and build on it.
It is specific to Thai legibility so may not very helpful generally for other
languages' characters.

_______________________________

A Thai display-character pack for Pebble watches (built and tested on the
**Pebble Time 2**), generated with
[Pyxzure/pebble-lang-gen](https://github.com/Pyxzure/pebble-lang-gen).
Drop in `thai-langpack.pbl` to read Thai text — SMS, notifications, weather,
calendar — on an otherwise-English watch, without a full interface
translation.

This isn't just a stock run of the generator, though. The default output is
readable but has real problems on a 1-bit display at watch sizes: inconsistent
stroke weight, tone marks colliding with vowels, and Thai rendering taller and
heavier than the English text next to it. Most of this repo is the fix for
those problems, described below.

## What's in the pack

- Full Thai Unicode block (`U+0E00`–`U+0E7F`): consonants, vowels, tone
  marks, and digits (๐–๙)
- Applied to every Pebble font slot (small UI text through large watchface
  display fonts), so Thai shows up consistently across the system, not just
  in notifications
- Sized and weighted to sit visually consistent with the stock English
  bitmap font at every size

## The problems, and what fixes them

Everything here comes from the same root cause: **PebbleOS draws one glyph
per codepoint with no OpenType shaping.** Fonts assume a shaping engine will
run their `GPOS` rules to fine-tune mark positioning; Pebble never runs one,
so several things that "just work" in a browser or on Android break here.

### 1. Blurry, inconsistent strokes

The default FreeType render path in `fontgen.py` rasterizes in mono mode but
doesn't force FreeType's autohinter. Thai stems that should be a uniform
width came out 2px in some places and 3–4px in others, because nothing was
snapping them to the pixel grid.

**Fix:** force `FT_LOAD_FORCE_AUTOHINT` when loading glyphs
(`utils/fontgen.py`, `glyph_bits_ttf`). This alone took stroke consistency
from roughly 60% single-width to 90%+.

### 2. Tone marks colliding with vowels

Thai stacks up to three levels vertically: a consonant, then an optional
**above-vowel** (◌ั ◌ิ ◌ี ◌ึ ◌ื ◌็ ◌ํ), then an optional **tone mark** (◌่ ◌้ ◌๊ ◌๋ ◌์)
sitting above that. Fonts position the tone mark assuming a shaping engine
will lift it clear of the vowel via `GPOS` mark-to-mark rules. Without that,
both marks render at the same fixed height and overlap — this is what makes
เนื้อ, น้ำ, and ดิ์ look like ink blots instead of text.

**Fix:** `Font.compute_thai_mark_raise()` in `utils/fontgen.py` measures, per
font size, how tall the tallest above-vowel renders, then computes a
per-codepoint upward shift for each tone mark so it clears that vowel with a
1px gap. The shift is capped so a mark can never be pushed out of the line
box. `build.py` calls this once per variant after font setup
(`THAI_MARK_CLEARANCE` controls the gap).

This is a general fix for the Thai script on non-shaping renderers, not a
one-off hack — it'll apply correctly to any Thai TTF dropped into `ttf/`.

### 3. Marks intruding into the line above / below

Even after fix #2, tone marks raised to clear a vowel could still poke into
the descender zone of the line above (visible as marks touching the bottoms
of English letters like g/y/p on the previous line). Thai below-vowels
(ุ ู) also descend further past the baseline than Latin descenders do, at
the same font size.

**Fix, take one (rejected):** scale tone marks/vowels down independently of
the base letters so the whole stack fits in less vertical space. This
technically worked — no more collisions — but it distorted the script:
marks that should read as the same weight as the letters they attach to
looked shrunken and "off," especially at small sizes.

**Fix, take two (shipped):** shrink the *entire* Thai font uniformly instead,
sized per font slot so the Thai cap height lands around 70–80% of the
matching Latin cap height (Thai needs more vertical room for the same
apparent size — this ratio is what let it fit without the two scripts
looking mismatched). Marks keep their natural proportions relative to the
base letters; only the overall scale changes. `make_fonts_json.py` in this
repo picks, for every variant, the tallest Thai size that still leaves
enough headroom above the raised tone mark to clear the previous line's
descenders.

### 4. Thai reading bolder (or thinner) than the English next to it

Because Thai was rendered at a single default weight regardless of size, its
mono-rendered strokes could look bold against a 1px-stem Latin size, or thin
against a 2px-stem one. The stock Pebble bitmap font (Renaissance) isn't a
single weight — it's 1px stems at most sizes but 2px at the 28px body-text
size, with separate 2px/3px bold variants.

**Fix:** assign a specific Noto Sans Thai Condensed weight *per font slot*,
matched to the measured stem width of the Latin bitmap font in that same
slot (Light for 1px-stem slots, Medium/SemiBold for the 2px/3px slots, and
so on). This is what `make_fonts_json.py` encodes — see the table in that
script for the current mapping. `fauxbold` (Pebble's synthetic bold, which
just smears the glyph one pixel over) is turned off everywhere in favor of
using real weight files.

## Known limitations

- **Vowel-over-tall-consonant collisions** (ปี่, ฝึก, ฟื้น) are not fixed.
  Fonts normally shift an above-vowel sideways when it sits over a
  tall-ascender consonant like ป ฝ ฟ, via the same `GPOS` machinery Pebble
  doesn't run. That needs horizontal context a static per-codepoint bitmap
  can't encode, so these still touch slightly. This is a pre-existing
  condition in the source font, not something introduced by this fork.
- **ำ (sara am)** has its own circle baked into the glyph at above-vowel
  height, so a raised tone mark can still lightly touch it (น้ำ).
- **Large display font variants (011–020)** are less tested. Weights for
  those were assigned by matching the *name* of the Latin display face they
  replace (e.g. Bitham Black → Thai Bold) rather than a measured stem width,
  since no `.pbff` reference exists for those sizes in this pipeline. If a
  watchface you use looks off, check `lang/fonts.json` for that slot.
- Interface strings (menus, settings, app names) are **not** translated —
  this pack only adds Thai *display* support, so the OS chrome stays
  English. `translation/000.po` still carries the full interface-translation
  workflow the upstream tool supports, if you want to extend this.

## Building

```bash
git clone <this repo>
pip install freetype-py --break-system-packages
python make_fonts_json.py   # regenerates lang/fonts.json with the size/weight table
python build.py             # outputs build/langpack.pbl
```

`lang/unicodes.json` controls which codepoints get pulled in (currently just
the Thai block). `lang/fonts.json` maps each of the 20 Pebble font slots to
a TTF, pixel height, baseline offset, and bold flag — `make_fonts_json.py`
computes this automatically from the target cap heights and headroom
constraints described above, so edit the tables at the top of that script
rather than `fonts.json` directly.

## Installing

1. Save `langpack.pbl` to your phone (Files/Downloads) rather than opening
   it straight from a browser tab — some Android browsers corrupt the
   install this way.
2. Open the file with the Pebble app and confirm.
3. The watch reboots with the new pack loaded. This replaces whichever
   language pack is currently installed — the watch holds one at a time.
